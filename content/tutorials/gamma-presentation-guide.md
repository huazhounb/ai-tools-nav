# 用 Gamma 生成一份可修改的项目汇报初稿

这篇教程适合需要做项目复盘、课程讲义、销售提案和内部汇报的人。Gamma 的价值不是替你一次性完成最终 PPT，而是把零散材料变成一个可讨论、可删改的演示结构。

## 准备材料

- 汇报对象：老板、客户、同学还是团队成员。
- 汇报时长：5 分钟、15 分钟或 30 分钟。
- 原始材料：项目背景、数据、结论、下一步计划。
- 必须出现的限制：不能公开的数据、不能承诺的结果、必须保留的术语。

## 操作步骤

1. 先把材料整理成“背景、目标、过程、结果、问题、下一步”六段。
2. 在 Gamma 中选择生成演示文稿，而不是只生成普通文档。
3. 输入任务说明，明确页数、听众和语气。
4. 生成后先检查大纲，不要急着美化页面。
5. 删除空泛页，把每页标题改成结论句。
6. 补充真实数据、截图和引用来源。
7. 导出前逐页检查事实、品牌色和敏感信息。

## 可复制提示词

```text
请根据以下材料生成一份 {{页数}} 页的项目汇报演示文稿初稿。

听众：{{听众}}
汇报时长：{{时长}}
汇报目标：{{希望听众做出的决定}}
语气：专业、克制、结论先行，不夸大成果。

每页要求：
1. 标题必须是结论句。
2. 正文不超过 4 个要点。
3. 对不确定的数据标注“待确认”。
4. 最后一页给出下一步行动建议。

项目材料：
{{粘贴项目材料}}
```

## 常见错误

- 只输入一句主题：生成结果会很像模板文案，缺少可用信息。
- 不写听众：面向客户和面向内部复盘的表达重点完全不同。
- 不核对数据：AI 可能补出看似合理但并不存在的数字。
- 直接使用默认页标题：建议改成“本月转化率下降主要来自新客渠道”这类结论句。

## 实际使用建议

如果是正式汇报，先用 Gamma 生成结构，再回到 WPS、PowerPoint 或 Keynote 做最终版。把 Gamma 当成“结构草稿工具”，不要把它当成“免审稿交付工具”。

## 相关工具

- Gamma：适合快速生成演示初稿。
- WPS AI：适合在中文办公文档里继续改稿。
- Kimi：适合先把长材料总结成大纲。
