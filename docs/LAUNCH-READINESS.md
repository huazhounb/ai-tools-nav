# 上线可用性缺口与优化建议

本文档用于判断当前 AI 工具导航站从“本地可演示项目”到“可正式部署给用户使用的产品”还缺什么。结论先行：当前项目已经具备页面雏形、导航结构、工具卡、教程、提示词、对比、榜单和投稿后台雏形，但距离正式上线还需要补齐稳定性、真实内容、数据一致性、SEO 可信度、后台持久化和基础运营闭环。

## 一、上线前必须补齐

### 1. 修复所有中文乱码

当前项目里仍存在历史乱码风险，尤其是部分旧文档、`data/comprehensive.ts`、`.env.example`、`nuxt.config.ts`、部分组件和 server 文案。正式上线前必须清理。

落地动作：

- 全站搜索乱码特征，例如 `涓`、`鎻`、`姒`、`瀵`、`歿`、`�`。
- 优先修复用户可见页面：工具详情、分类页、首页、教程页、提示词页、对比页、榜单页、提交页。
- 修复 SEO title、description、FAQ、JSON-LD 中的乱码。
- 所有源码、Markdown、配置文件统一 UTF-8。

验收标准：

- 主要页面没有乱码。
- sitemap 中的 URL 和页面标题正常。
- 浏览器页面标题、描述和正文中文可读。

### 2. 确认核心页面真实可用

现在页面结构已经比较完整，但正式上线前需要逐页走真实用户路径。

必须验证的页面：

- `/`
- `/tools/free`
- `/category`
- `/category/ai-writing`
- `/tool/chatgpt`
- `/tutorial`
- `/tutorial/chatgpt-guide`
- `/prompts`
- `/prompts/weekly-report-summary`
- `/compare`
- `/compare?tools=chatgpt,claude,deepseek`
- `/compare/deepseek-vs-doubao-vs-tongyi`
- `/rankings`
- `/rankings/free-ai-tools`
- `/submit`
- `/admin/submissions`

落地动作：

- 检查导航是否都能打开。
- 检查动态 slug 不存在时是否 404。
- 检查筛选、搜索、复制、点赞、投稿是否可用。
- 检查移动端是否可读，尤其是筛选栏和对比表格。

验收标准：

- 没有空白页。
- 没有“建设中”。
- 没有控制台报错。
- 用户能从首页进入工具详情、教程、提示词、对比和榜单。

### 3. 修复搜索体验

用户多次反馈首页搜索框不可用。搜索是导航站第一核心功能，必须优先解决。

落地动作：

- 首页搜索框支持手动输入中文、英文、工具名、任务词。
- 支持 Enter 搜索。
- 支持搜索按钮。
- 支持清空按钮。
- 支持中文输入法 composition，不要输入拼音过程中误触发。
- 搜索无结果时给出推荐词。
- 搜索结果应能进入工具详情页。

建议后续增强：

- `/search` 做成全站搜索结果页。
- 搜索范围覆盖工具、教程、提示词、对比、榜单。
- 增加 URL query，例如 `/search?q=PPT`，便于分享和收录。

### 4. 统一数据模型

当前项目存在多套数据来源和字段并存的问题：

- `data/comprehensive.ts`
- `data/mock-tools.ts`
- `data/tools.ts`
- `data/siteContent.ts`
- `content/**` Markdown

字段也有重复：

- `pricing` / `freeStatus`
- `audience` / `audiences`
- `platform` / `platforms`
- `body` / `prompt`
- `models` / `applicableModels`

落地动作：

- 确定首版唯一主数据源。
- 推荐短期用 `data/mock-*.ts`，中期迁移数据库。
- 所有页面统一从同一套数据读取。
- 保留兼容字段前，先写清楚哪个字段是主字段。

验收标准：

- 同一个工具在首页、分类页、详情页、榜单页显示一致。
- 同一个提示词在列表页和详情页内容一致。
- 分类页不再因为字段不一致出现工具缺失。

### 5. 投稿和后台审核需要持久化

当前投稿审核如果仍是内存存储，服务重启后数据会丢失。正式上线不能依赖内存数组。

最低可上线方案：

- 使用 SQLite 或 PostgreSQL 保存投稿。
- `submissions` 表至少包含：
  - `id`
  - `type`
  - `name`
  - `website`
  - `category`
  - `description`
  - `free_status`
  - `chinese_support`
  - `reason`
  - `submitter_name`
  - `contact`
  - `status`
  - `review_note`
  - `created_at`
  - `updated_at`

必须补齐：

- 后台审核权限保护。
- 防止重复提交。
- 基础频率限制。
- 投稿成功提示。
- 审核状态可更新。

### 6. 点赞和榜单热度需要持久化

当前点赞如果使用内存 Map，只适合本地演示。上线后重启会丢失，且不能防刷。

最低可上线方案：

- 数据库表 `tool_likes`。
- 匿名用户用 `anonymous_id` 或浏览器 localStorage 标记。
- 服务端增加 IP hash 或频率限制。
- 榜单分数定时或请求时计算。

建议表：

- `tool_likes`
- `tool_views`
- `ranking_items`

### 7. SEO 基础必须真实可索引

项目定位依赖 SEO，不能只做首页。

上线前必须确认：

- 每个页面唯一 H1。
- 每个页面有 `useSeoMeta`。
- 动态详情页有 canonical。
- sitemap 覆盖全部工具、分类、教程、提示词、对比、榜单。
- robots 禁止 `/admin`。
- FAQ JSON-LD 只输出页面真实存在的 FAQ。
- 核心正文不是客户端点击后才出现。

重点页面：

- 工具详情页
- 分类页
- 免费工具页
- 对比页
- 教程页
- 提示词页
- 榜单页

### 8. 品牌图标授权与 fallback

工具导航站很依赖品牌识别，但品牌图标不能随便热链或暗示官方合作。

上线前必须确认：

- 页面只加载 `public/brand-icons/` 本地图标。
- 没有外部热链。
- 没有“官方合作”误导文案。
- `docs/brand-icons.md` 写清来源策略。
- 抓取失败的工具使用自制占位图标，而不是丑的字母块。

## 二、内容层面还缺什么

### 1. 工具详情页需要更像真实测评

当前工具详情如果只是模板化介绍，用户不会信任。

建议每个核心工具补齐：

- 一句话结论。
- 实测场景。
- 免费额度说明。
- 中文输入、中文输出、中文界面分别说明。
- 适合谁、不适合谁。
- 真实任务示例。
- 替代工具。
- 相关教程。
- 相关提示词。
- 更新时间和检查日期。

首批重点工具：

- ChatGPT
- DeepSeek
- Claude
- 豆包
- 通义千问
- Kimi
- Midjourney
- Cursor
- Canva AI
- Gamma
- Perplexity
- 秘塔 AI 搜索

### 2. 分类页需要补“选型正文”

分类页不能只是卡片列表。

每个分类建议补：

- 这个分类解决什么问题。
- 新手怎么选。
- 免费工具怎么判断。
- 中文用户注意事项。
- 推荐组合。
- FAQ。
- 相关教程和提示词。

首批优先分类：

- AI 写作
- AI 对话
- AI 绘图
- AI PPT
- AI 编程
- AI 办公
- AI 论文研究
- AI 搜索

### 3. 教程需要真实任务驱动

教程页已经往学习中心方向改，但内容还要继续提高实用性。

优质教程结构：

- 适合人群。
- 预计耗时。
- 准备材料。
- 操作步骤。
- 可复制提示词。
- 常见错误。
- 结果检查清单。
- 替代工具。
- 下一步学习。

不建议写：

- “AI 是什么”这类泛科普。
- 没有实际步骤的软文。
- 只改标题不改正文的批量文章。

### 4. 提示词库要保证每条可直接用

提示词库的价值在于复制后能完成任务。

每条提示词建议补：

- 使用场景。
- 适用模型。
- Prompt 正文。
- 变量说明。
- 示例输入。
- 示例输出摘要。
- 失败原因。
- 优化建议。
- 相关工具。

必须避免：

- 同一模板改几个词重复生成。
- 太空泛的万能 Prompt。
- 不说明变量怎么替换。

### 5. 对比页需要真实差异

对比页是高转化 SEO 页面，不能只写“各有优势”。

每个对比页必须明确：

- 谁适合免费使用。
- 谁中文更好。
- 谁更适合写作。
- 谁更适合代码。
- 谁更适合办公。
- 谁学习成本更低。
- 最终怎么选。

建议首批重点对比：

- DeepSeek vs 豆包 vs 通义千问
- ChatGPT vs Claude vs Gemini
- Midjourney vs Stable Diffusion vs 即梦 AI
- Gamma vs Canva AI vs Tome
- Cursor vs GitHub Copilot vs Codeium

### 6. 榜单需要透明规则

榜单不能像普通合集。

建议每个榜单展示：

- 排名规则。
- 权重说明。
- 编辑评分。
- 用户点赞。
- 浏览量或热度。
- 更新时间。
- 工具入选理由。

用户会关心：

- 为什么它是第 1 名？
- 是不是广告？
- 免费工具和付费工具有没有分开？
- 排名多久更新一次？

## 三、工程和部署还缺什么

### 1. 生产环境配置

需要补齐：

- `NUXT_PUBLIC_SITE_URL` 改为正式域名。
- `NUXT_PUBLIC_SITE_NAME` 改为正式站名。
- `NUXT_ADMIN_TOKEN` 使用强随机值。
- 数据库连接字符串。
- 日志和错误追踪。
- robots 和 sitemap 的正式域名。

### 2. 运行检查

上线前建议至少跑：

```bash
npm run build
npm run preview
```

并人工打开：

- 首页
- 工具详情
- 分类页
- 教程详情
- 提示词详情
- 对比详情
- 榜单详情
- 投稿页
- 后台审核页
- robots
- sitemap

### 3. 错误监控

建议接入：

- Vercel / Netlify 部署日志。
- 基础前端错误监控。
- API 错误日志。
- 投稿失败日志。
- 点赞接口失败日志。

### 4. 安全与风控

上线前最低要求：

- `/admin/submissions` 必须有权限保护。
- 投稿接口需要频率限制。
- 点赞接口需要防重复和基础防刷。
- 外链打开建议 `rel="nofollow noopener"`。
- 用户提交内容不要直接渲染 HTML。

### 5. 性能

需要检查：

- 首页首屏是否过重。
- 品牌图标是否本地加载。
- 图片是否懒加载。
- 对比表移动端是否横向滚动。
- 列表页数据量变大后是否需要分页。

## 四、运营闭环还缺什么

### 1. 内容更新机制

建议建立每周内容节奏：

- 新增 5-10 个工具。
- 新增 2-3 篇教程。
- 新增 5 个提示词。
- 更新 1 个榜单。
- 检查失效工具和价格变化。

### 2. 工具失效检查

每个工具需要：

- `status`
- `checkedAt`
- `statusNote`
- 官方链接检查结果。

页面应提示：

- 可用。
- 待确认。
- 可能失效。

### 3. 广告和合作规则

当前已有 SponsorSlot 思路，但上线前要明确：

- 广告必须标注“合作”“赞助”或“广告”。
- 不做弹窗。
- 不做大面积干扰阅读的横幅。
- 商业位不能混入自然榜单。
- 合作工具也要保留真实优缺点。

### 4. 用户反馈入口

建议补：

- 工具信息纠错入口。
- 失效链接反馈。
- 投稿成功后的审核说明。
- 联系邮箱。
- 合作说明页。

## 五、上线优先级建议

### P0：不上线会影响用户使用

1. 修复乱码。
2. 修复首页搜索。
3. 确认所有导航和动态详情页可打开。
4. 投稿和后台审核持久化。
5. robots 禁止后台，sitemap 覆盖核心页面。
6. 正式域名、环境变量和部署配置。

### P1：上线后影响留存和 SEO

1. 补强 30 个核心工具详情页。
2. 补强 8 个核心分类页正文。
3. 补强 20 个高质量提示词。
4. 补强 10 篇任务型教程。
5. 补强 8 个高意图对比页。
6. 榜单规则透明化和点赞持久化。

### P2：产品体验优化

1. 全站搜索结果页。
2. 工具纠错入口。
3. 内容更新时间展示。
4. 工具收藏。
5. 更细的筛选和排序。
6. 移动端导航优化。

### P3：暂缓

1. 复杂账号体系。
2. 评论区。
3. 积分系统。
4. 厂商自助广告后台。
5. 自动爬虫批量采集。
6. 多语言站点。

## 六、推荐上线版本定义

建议第一版正式上线不要追求功能多，而是保证这些能力稳定：

- 用户能搜索工具。
- 用户能按分类找工具。
- 用户能看工具详情和替代工具。
- 用户能复制提示词。
- 用户能学习教程。
- 用户能查看对比和榜单。
- 用户能提交工具。
- 管理员能审核投稿。
- 搜索引擎能抓取核心页面。

如果这些都稳定，项目就具备“可给真实用户使用”的基础。
