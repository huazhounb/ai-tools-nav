# 中文 AI 工具导航内容产品前期研究

## 结论先行

本项目不应和 AI 工具黄页拼“收录数量”，而应抢占“中文用户完成具体任务前的选择入口”。当前竞品大多已经覆盖工具收录、分类、榜单、投稿和广告位，但普遍把用户停留在“看见很多工具”的阶段，没有稳定解决三个问题：该选哪个、怎么上手、拿什么提示词直接开用。

推荐定位为：

> 面向中文用户的 AI 工具选择与上手内容产品：用场景方案、教程、可复制提示词和工具对比，帮助用户从“知道工具”走到“完成任务”。

MVP 应优先做 6 类页面：首页、分类页、工具详情页、教程页、提示词页、对比页。后台只做工具与内容审核，不做复杂账号、社区、积分和厂商自助投放。

## 1. 市场机会

### 机会一：工具导航供给过剩，但“决策内容”不足

AIBase、发现AI、AI工具集、悠智AI导航、360AI导航、Toolify 都已经证明“AI 工具目录”是高需求入口。Toolify 首页直接展示 29000+ AI、459 个分类，并把 New、Most Saved、Most Used、Top by Monthly Visits 等榜单作为核心入口。AI工具集、发现AI、悠智AI导航也都有大量分类、热门工具和教程资源。

但这类站的主要价值仍是“找到工具”，不是“替用户做选择”。用户真正搜索的是：

- “做 PPT 用什么 AI”
- “免费 AI 绘图工具哪个好”
- “Kimi 和豆包哪个适合写论文”
- “新手怎么用 DeepSeek 写周报”
- “小红书文案提示词模板”

落地功能：每个分类页都要有“怎么选”模块，而不是只列工具卡片。每个工具详情页都要有“适合谁 / 不适合谁 / 免费额度 / 替代品 / 上手教程 / 可复制提示词”。

### 机会二：中文用户更需要“可执行教程”，不是英文产品介绍

发现AI有“AI操作手册”和高阶指令词，AI工具集有教程资源、AI百科、AI问答，说明教程内容已经成为导航站的流量与留存入口。但多数教程仍偏资讯聚合或单篇文章，缺少统一模板和场景闭环。

落地功能：建立教程模板：

- 适用场景
- 准备材料
- 操作步骤
- 可复制提示词
- 常见失败原因
- 替代工具
- 相关对比

### 机会三：提示词是低门槛、高复访内容

Toolify 已把 Prompts 作为一级入口，发现AI有高阶AI指令词，AI工具集有 AI提示指令分类。这说明提示词不仅是内容补充，而是独立流量入口。

落地功能：首版做“提示词库”，按场景而不是按模型组织。例如：周报、论文润色、小红书标题、短视频脚本、PPT大纲、SQL解释、简历优化。

### 机会四：对比页承接高意图 SEO

用户在购买或深度使用前会搜索“X 和 Y 哪个好”。竞品虽有榜单，但对比解释通常不足。对比页比单个工具页更接近决策，也更容易承接长尾搜索。

落地功能：首批固定做：

- `ChatGPT vs Claude`
- `Kimi vs 豆包`
- `DeepSeek vs 通义千问`
- `Midjourney vs 即梦AI`
- `Cursor vs Trae`
- `秘塔AI搜索 vs Perplexity`

## 2. 用户需求

| 用户类型 | 核心需求 | 应落地页面/功能 |
|---|---|---|
| AI 新手 | 不知道从哪个工具开始 | 新手入门页、免费工具页、首页“按任务找工具” |
| 职场办公用户 | 写周报、做 PPT、总结文档、整理会议 | 办公分类页、PPT教程、文档总结教程、办公提示词包 |
| 学生/论文用户 | 查资料、读论文、润色、降重、做引用 | 学术分类页、论文工具对比、论文提示词模板 |
| 自媒体/内容创作者 | 标题、脚本、配图、短视频、选题 | 内容创作场景页、小红书/公众号/短视频提示词页 |
| 设计师/电商 | 生图、修图、商品图、海报 | 设计分类页、商品图教程、图像工具对比 |
| 程序员 | 编程 IDE、代码解释、Agent、文档生成 | 编程分类页、Cursor/Trae 对比、AI 编程教程 |
| AI 厂商 | 曝光、投稿、排名、广告 | 投稿页、合作页、赞助位规范 |

关键判断：用户不是按“工具类型”开始，而是按“任务”开始。分类可以保留，但首页和 SEO 页面必须用任务语言组织。

| 360AI导航 | 大厂背书，和 360 AI 产品矩阵联动，适合导流到自家应用 | 更像大厂 AI 产品入口，不是中立评测导航 | “AI 应用矩阵”式聚合和会员/生态入口 | 不绑定单一厂商立场 |
| Toolify.ai | 国际化、数据规模、榜单体系、提交/广告/客座文章商业化成熟 | 英文环境为主，对中文用户上手支持弱，广告位明显 | New/Most Used/Most Saved、提交、广告、Prompt 一级入口 | 不追求 2 万+工具规模 |
| AI工具集 | 中文分类完整，教程资源、百科、快讯、项目收录丰富 | 老式导航感较强，入口多但决策辅助不足 | 分类体系、教程资源、AI百科 | 不做百科式大而全内容堆叠 |
| 悠智AI导航 | 覆盖工具、测评、资源、资讯，分类和文章量大 | 内容质量容易变成采集式摘要，缺少统一决策框架 | “工具 + 测评 + 资讯”组合 | 不把资讯流作为首页主干 |

## 4. 竞品 UI 优缺点

### 共性优点

- 搜索框都放在显著位置，说明“直接找工具”是高频行为。
- 分类导航丰富，利于 SEO 和爬虫发现页面。
- 卡片式工具列表成熟，用户理解成本低。
- 榜单、热门、新收录模块能制造更新感。

### 共性问题

- 首页信息密度过高，用户第一屏容易被分类、广告、榜单、资讯同时抢注意力。
- 工具卡片多停留在一句话介绍，缺少“为什么推荐”和“适合什么任务”。
- 广告和推荐混在一起时，信任感下降。
- 分类以工具能力命名多，以用户任务命名少。
- 教程、提示词、对比页和工具详情之间的互链不足。

### 本项目 UI 方向

首页第一屏只解决一个问题：让用户按任务找到入口。

建议结构：

- 顶部搜索：支持工具名、任务、场景关键词。
- 主入口：`找工具`、`看教程`、`复制提示词`、`做对比`。
- 场景快捷入口：办公、写作、设计、视频、编程、学习、运营。
- 推荐工具不超过 8 个，必须给出推荐理由。

工具卡片字段：

- 工具名
- 一句话用途
- 免费/付费/国内可访问
- 适合场景标签
- 推荐理由
- 快速入口：详情、教程、提示词、对比

## 5. 竞品商业化方式

| 商业化方式 | 竞品体现 | 可落地做法 | 风险控制 |
|---|---|---|---|
| 赞助工具位 | Toolify 首页 Sponsor 明显 | 首页赞助位、分类页赞助位、详情页相关推荐 | 必须标注“赞助” |
| 工具提交 | Toolify 有 Submit，国内站普遍有投稿/收录 | 投稿页 + 后台审核 | 不承诺自然排名 |
| 广告合作 | Toolify 有 Advertise、Guest Posts / Link Insert | 合作页提供广告位说明和报价入口 | 广告不混入编辑推荐 |
| 软文/客座文章 | Toolify 明确有 Guest Posts | 厂商案例文章、教程合作 | 标注“合作内容” |
| 联盟佣金 | SaaS 工具常见 | 出海工具、会员订阅工具可接 affiliate | 不影响评测结论 |
| 企业服务 | 360 面向企业/行业客户 | 后期做企业 AI 工具选型报告 | MVP 不做定制咨询系统 |

MVP 推荐只做三种：

1. 投稿页
2. 赞助位标注
3. 合作页

先不要做复杂厂商后台，避免审核、支付、发票、排名争议拖慢主线。

## 6. 本项目差异化定位

### 定位一句话

中文用户的 AI 工具选择与上手手册。

### 差异化主张

| 维度 | 常规导航站 | 本项目 |
|---|---|---|
| 核心价值 | 收录更多工具 | 帮用户选对工具并用起来 |
| 首页逻辑 | 分类 + 热门工具 | 任务入口 + 教程 + 提示词 + 对比 |
| 工具详情 | 工具介绍 | 适合谁、怎么用、替代品、提示词 |
| SEO 重点 | 工具名、分类名 | 场景词、对比词、教程词、免费词 |
| 内容资产 | 摘要和资讯 | 可复用模板、教程、Prompt、决策表 |
| 信任机制 | 热门/推荐 | 实测说明、优缺点、商业标注 |

### 必须坚持的产品边界

- 可以收录工具，但不能让“收录量”成为唯一目标。
- 可以做榜单，但榜单必须解释排名理由。
- 可以商业化，但商业位必须透明标注。
- 可以做教程，但每篇教程必须连接到工具、提示词和相关对比。

## 7. MVP 功能优先级

### P0：必须首版上线

| 功能 | 页面/模块 | 目的 |
|---|---|---|
| 首页 | `/` | 建立任务入口、搜索、推荐内容 |
| 分类页 | `/category/[slug]` | 承接分类 SEO 和浏览 |
| 工具详情页 | `/tool/[slug]` | 承接工具名 SEO，沉淀决策信息 |
| 教程页 | `/tutorial/[slug]` | 提供上手路径，提高停留时长 |
| 提示词页 | `/prompts/[slug]` | 提供可复制资产，提高复访 |
| 对比页 | `/compare/[a]-vs-[b]` | 承接高意图搜索 |
| 免费工具页 | `/free-ai-tools` | 承接“免费”强需求 |
| 投稿页 | `/submit` | 获取供给和厂商线索 |
| 合作页 | `/advertise` 或 `/cooperation` | 明确商业化入口 |
| sitemap/robots/JSON-LD | 技术 SEO | 提高收录效率 |

### P1：首版后 2-4 周

| 功能 | 页面/模块 | 目的 |
|---|---|---|
| 榜单页 | `/rankings/[slug]` | 做热门和分类排行 |
| 场景方案页 | `/solutions/[slug]` | 把多个工具组合成任务流程 |
| 新手专区 | `/learn-ai` | 承接新手流量 |
| 工具替代品 | 工具详情模块 | 提高内链密度 |
| 内容标签页 | `/tags/[slug]` | 扩展长尾 SEO |

### P2：暂缓

| 功能 | 暂缓原因 |
|---|---|
| 用户登录/收藏 | 会拖慢 MVP，且不影响 SEO 冷启动 |
| 评论系统 | 审核成本高，早期价值有限 |
| 厂商自助后台 | 涉及支付、审核、排名争议 |
| 自动爬虫大规模采集 | 容易造成低质内容和版权风险 |
| 多语言 | 当前定位是中文用户 |

## 8. 不建议做的功能

1. 不做“大而全工具黄页”
   - 落地约束：首批工具控制在 100-200 个高质量工具，每个工具必须有用途标签、适合人群和替代品。

2. 不做首页资讯流
   - 落地约束：首页最多保留“最新教程/最新工具”模块，不放行业新闻瀑布流。

3. 不做复杂账号体系
   - 落地约束：投稿用表单即可，后台只做审核。

4. 不做无解释榜单
   - 落地约束：榜单必须有排序规则，例如免费额度、中文支持、上手难度、输出质量、国内访问。

5. 不做伪评测
   - 落地约束：没有实测时写“资料整理”，不要写“深度测评”。

6. 不做广告伪装推荐
   - 落地约束：所有商业位显示“赞助/合作/广告”标签。

7. 不做早期厂商会员后台
   - 落地约束：先用人工审核 + 邮件/表单合作，等流量稳定后再产品化。

## 10. 推荐首页信息架构

### 第一屏

目标：让用户 5 秒内知道这里不是普通网址导航。

模块：

- H1：`找到适合你的 AI 工具，并直接用起来`
- 副标题：`AI 工具选择、上手教程、场景方案和可复制提示词`
- 搜索框：支持搜索工具名、任务、场景
- 四个主入口：
  - 找 AI 工具
  - 看上手教程
  - 复制提示词
  - 做工具对比

### 第二屏：按任务找工具

模块：

- 写文章/周报
- 做 PPT
- 读论文
- 生成图片
- 剪视频
- 写代码
- 做小红书
- 做电商商品图

每个任务卡片包含：

- 推荐 3 个工具
- 1 篇教程
- 1 组提示词

### 第三屏：热门工具推荐

只放 6-8 个，不做长列表。

每个卡片必须包含：

- 推荐理由
- 免费/付费
- 适合人群
- 详情入口

### 第四屏：最新上手教程

教程卡片字段：

- 场景
- 预计耗时
- 适合人群
- 涉及工具
- 是否附提示词

### 第五屏：可复制提示词

按场景展示：

- 办公
- 写作
- 学习
- 编程
- 设计
- 运营

每个提示词卡片要有“复制”按钮和“查看变量说明”。

### 第六屏：工具对比

推荐展示 4-6 个高搜索意图对比：

- Kimi vs 豆包
- DeepSeek vs 通义千问
- Cursor vs Trae
- Midjourney vs 即梦AI
- 秘塔AI搜索 vs Perplexity

### 第七屏：投稿与合作

模块：

- 提交 AI 工具
- 申请更新工具信息
- 广告/赞助合作
- 内容合作说明

必须明确：投稿不等于推荐，商业合作会标注。
